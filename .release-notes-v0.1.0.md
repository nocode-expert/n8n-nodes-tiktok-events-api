First release.

Sends server-side conversion events to the TikTok Events API 2.0 from n8n, with the normalization and hashing done to TikTok's spec.

### Why

The usual approach is a Crypto node per PII field, a Code node to build the payload, and an HTTP Request node with the token in a header. Every way that breaks is invisible, because TikTok answers `code: 0` either way:

- a Crypto node runs whether or not the field has a value, so a missing email is sent as `SHA256("")` — a well-formed hash of nobody
- TikTok's rules are not Meta's: phone numbers must be E.164 **including** the `+`, and email is hashed without the Gmail dot-stripping Meta applies
- hashing an already-hashed value silently destroys the match
- a token in the workflow JSON travels with every export

### What it does

- Map raw values; the node normalizes and SHA-256 hashes them to TikTok's spec
- Absent fields are omitted rather than hashed empty
- Already-hashed values are detected and passed through, checked **before** normalizing, because a normalizer applied to a digest destroys it
- The token lives in an n8n credential, not the workflow
- Validates before sending, since TikTok will not: Value a number or genuinely empty, Event Time a recognisable timestamp, and at least one identifier surviving normalization
- Test Event Code support for validating in Events Manager before going live
- Usable as an AI tool

Every normalization rule is unit-tested against the examples in TikTok's own documentation. No runtime dependencies. MIT.
